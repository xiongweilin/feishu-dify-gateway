# ADR-001：使用飞书长连接与专用 Dify Chatflow

## 状态

Superseded by ADR-002（2026-08-07：改用控制平面 Codex 派发，移除 Dify Chatflow）

## 日期

2026-08-02

## 背景

个人平台需要一个国内稳定可达、支持私聊交互和主动告警的消息渠道，同时避免新增公网回调域名、证书和常驻公网入口。消息可能包含个人输入和内部告警，因此需要最小权限、可追踪失败和明确的数据保留边界。

## 决定

- 使用仅本人可见的飞书自建应用机器人。
- 使用飞书 SDK 长连接接收事件，不开放公网回调。
- 使用专用 Dify Chatflow 处理文本会话。
- 使用一个 WSL gateway 统一发送飞书消息、处理幂等、会话映射和指标。
- 云端 webhook relay 保留原始事件的最小字段，只有 gateway 确认投递后才删除队列项。
- 状态变更命令不进入 v1；所有运维命令只读。

## 备选方案

- 个人微信非官方机器人：拒绝，缺少稳定官方接口并有账号风险。
- Telegram Bot：拒绝作为主渠道，国内云服务器当前无法稳定访问其 API。
- 飞书公网 Webhook 回调：拒绝，长连接已满足需求且不需要新增公网入口。

## 后果

- WSL 主机离线时无法进行对话，但云端 relay 会保留通知并重试。
- 飞书或 gateway 故障由云端 watchdog 通过 Gmail 发出带外通知。
- 凭证分布在 WSL 与云端两个最小权限 secret 目录中；灾备副本进入既有密码库。
- 指标和日志不得包含消息正文、Token、邮件地址或原始飞书用户标识。
